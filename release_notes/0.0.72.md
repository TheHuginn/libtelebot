# 0.0.72 — единая конфигурация JSON-сериализации

`System.Text.Json` по умолчанию пишет `null`-свойства как явные `"field": null`. Для reply-markup эта проблема уже была закрыта локальным `ReplyMarkupJson.Options` (там `null` в поле-дискриминаторе union'а сломал бы распознавание типа), а в остальных запросах те же грабли лежали неприкрытыми и давали:

- лишний шум в теле запросов и в логах — `ReplyParameters(MessageId: 42)` уходил как ~200 байт JSON с семью явными `null` вместо ~15 байт;
- неконсистентное поведение соседних объектов (одни дропают `null`, другие нет);
- скрытый риск на будущее — если Telegram добавит поле, где `null` ≠ «не задано», выстрелит именно тут.

## Что сделано

Заведён общий `internal static class TelebotJson` в `Telegram.cs` с единым `JsonSerializerOptions`:

```csharp
internal static class TelebotJson
{
    public static readonly JsonSerializerOptions Options = new()
    {
        DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull,
    };
}
```

Класс `internal` — наружу опции не торчат, публичное API не меняется.

Все 10 вызовов `JsonSerializer.Serialize(...)` в библиотеке переведены на `TelebotJson.Options`:

- `SendMessageRequestParams` — `LinkPreviewOptions`, `ReplyParameters`
- `EditMessageTextRequestParams` — `LinkPreviewOptions`
- `SendPollRequestParams` — `Options[]`
- `GetUpdatesRequestParams` — `AllowedUpdates[]`
- `SetWebhookRequestParams` — `AllowedUpdates[]`
- `InlineKeyboardMarkup`, `ReplyKeyboardMarkup`, `ForceReply`, `ReplyKeyboardRemove` — раньше использовали локальный `ReplyMarkupJson.Options`

Локальный `ReplyMarkupJson` из `IReplyMarkup.cs` удалён — его функцию полностью взял на себя `TelebotJson`.

## Совместимость

Ломающих изменений нет. Затрагивается только формат исходящего JSON: у `LinkPreviewOptions`, `ReplyParameters` и им подобных `null`-поля перестанут появляться в теле запросов. Для массивов (`AllowedUpdates`, `InputPollOption[]`) поведение не меняется — они прогнаны через общие опции ради консистентности.
