У `DefaultTelegramTransport` теперь есть второй конструктор, принимающий `DefaultTransportOptions`. Можно переопределить `BaseAddress` (и `Timeout`, они логически ходят парой); всё остальное остаётся по умолчанию.

## Переопределение URL из переменной окружения

```csharp
using Telebot;

var baseAddress = Environment.GetEnvironmentVariable("TELEGRAM_API_URL") is { } url
    ? new Uri(url)
    : new Uri("https://api.telegram.org");

var transport = new DefaultTelegramTransport(new DefaultTransportOptions
{
    BaseAddress = baseAddress,
});

var bot = new Telegram(transport, "BOT_TOKEN");
```

Если переменная не задана — поведение прежнее. Если домен API снова переедет, достаточно выставить `TELEGRAM_API_URL=https://<новый-хост>` — без пересборки.

## Подмена URL на mock-сервер в тестах

Тот же конструктор — просто указываешь свой локальный стаб (WireMock, `HttpClient` handler-mock, self-hosted Bot API server — что удобнее):

```csharp
var transport = new DefaultTelegramTransport(new DefaultTransportOptions
{
    BaseAddress = new Uri("http://localhost:8081"),
    Timeout = TimeSpan.FromSeconds(5),
});

var bot = new Telegram(transport, "test-token");
```

## Про lifetime

`DefaultTelegramTransport` теперь владеет собственным `HttpClient`, собранным из переданных опций. Держи один инстанс транспорта на весь процесс (или по одному на каждого бота, если ботов несколько) и переиспользуй — пересоздание транспорта на каждый запрос приведёт к утечке сокетов. Это классическая .NET-грабля с `HttpClient`, не специфика библиотеки, но упомянуть стоит явно.

Если нужна более сложная настройка (прокси, свой `HttpMessageHandler`, логирование запросов) — реализуй свой `ITelegramTransport`; `DefaultTransportOptions` намеренно оставлен минимальным.
