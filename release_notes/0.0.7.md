# 0.0.7 — кнопки, которые живут

До этого релиза библиотека умела **отправлять** меню, но не умела с ним **работать дальше**: нельзя было ни поймать нажатие, ни погасить крутилку на кнопке, ни обновить сообщение после клика. 0.0.7 закрывает этот цикл — теперь inline-клавиатуры становятся полноценной сценой, а не декорацией под текстом.

## Что добавилось

### `editMessageText`

Метод `EditMessageTextAsync` заменяет текст ранее отправленного сообщения — и, по желанию, его инлайн-клавиатуру.

```csharp
await bot.EditMessageTextAsync(
    new EditMessageTextRequestParams(
        ChatId: 123456789,
        MessageId: 42,
        Text: "Готово ✅"
    ),
    CancellationToken.None
);
```

Реквест поддерживает `ParseMode`, `LinkPreviewOptions` и `ReplyMarkup`. `ReplyMarkup` типизирован как `InlineKeyboardMarkup?`, а не как общий `IReplyMarkup` — Telegram в этом методе принимает только инлайн-клавиатуру, компилятор теперь знает об этом ограничении.

Вариант вызова по `inline_message_id` (сообщения, отправленные через инлайн-режим) намеренно не добавлен: инлайн-режим в библиотеке пока не поддерживается вообще. Поле `entities` тоже пропущено — вернёмся к нему вместе с остальной rich-media поддержкой.

### `editMessageReplyMarkup`

`EditMessageReplyMarkupAsync` меняет **только** клавиатуру, не трогая текст. Полезно, когда после выбора нужно убрать теперь ненужные кнопки, а сам пост оставить как есть.

```csharp
await bot.EditMessageReplyMarkupAsync(
    new EditMessageReplyMarkupRequestParams(
        ChatId: 123456789,
        MessageId: 42,
        ReplyMarkup: null   // → клавиатура снимется
    ),
    CancellationToken.None
);
```

### `CallbackQuery` в `Update`

Добавилось поле `Update.CallbackQuery` и одноимённая модель `Telebot.Models.CallbackQuery`. Именно оно приходит через `getUpdates` (или webhook), когда пользователь нажал кнопку с непустым `callback_data`.

```csharp
foreach (var update in updates)
{
    if (update.CallbackQuery is { Data: { } data } cb)
    {
        // …обработать data…
    }
}
```

**Нюанс с `MaybeInaccessibleMessage`.** В API поле `message` у `CallbackQuery` — union-тип: либо обычное `Message`, либо «заглушка» `InaccessibleMessage` для удалённых или слишком старых сообщений. У заглушки заполнены только `chat` и `message_id`.

Отдельного типа под заглушку в библиотеке нет — оба варианта помещаются в существующий `Message`, потому что все его необязательные поля уже nullable. Отличить их друг от друга можно по документированному самим Telegram признаку: у обычного сообщения `Date` — реальный unix-timestamp, у заглушки **всегда** 0. Если поле 0 — сообщение недоступно, и всё, что с ним можно сделать, — сослаться на `chat.id` и `message_id`.

### `answerCallbackQuery`

`AnswerCallbackQueryAsync` подтверждает приём callback-запроса. Без него у пользователя на нажатой кнопке продолжает крутиться индикатор — до тех пор, пока Telegram сам не сдастся по таймауту.

```csharp
// Минимум — просто погасить индикатор:
await bot.AnswerCallbackQueryAsync(
    new AnswerCallbackQueryRequestParams(cb.Id),
    CancellationToken.None
);

// Или с тостом/алертом:
await bot.AnswerCallbackQueryAsync(
    new AnswerCallbackQueryRequestParams(
        CallbackQueryId: cb.Id,
        Text: "Сохранено",
        ShowAlert: false
    ),
    CancellationToken.None
);
```

Поддержаны `Text`, `ShowAlert`, `Url` и `CacheTime`. Из игровых сценариев ничего не завязано — `Url` включён из-за легитимного не-игрового применения (редирект в самого бота через `t.me/<bot>?start=…`).

## Обновлённый список методов

| Метод | Описание |
|---|---|
| `getMe` | информация о боте, проверка токена |
| `getUpdates` | long-polling новых событий |
| `sendMessage` | отправка текстовых сообщений |
| `sendPhoto` | отправка фото (file_id / URL / поток) |
| `sendPoll` | отправка опросов |
| `setWebhook` | регистрация webhook-URL |
| **`editMessageText`** | **новое:** редактирование текста сообщения |
| **`editMessageReplyMarkup`** | **новое:** замена/снятие инлайн-клавиатуры |
| **`answerCallbackQuery`** | **новое:** подтверждение приёма нажатия кнопки |

## Совместимость

Изменений, ломающих существующий код, нет. Новое поле `Update.CallbackQuery` объявлено с `= null`, поэтому существующие конструкции `new Update(...)` не требуют правок.
